## Phase Goal

**As a** recruiter evaluating the live demo, **I want to** watch the agent discover and call a real tool from a companion MCP server — with the call appearing in the reasoning trace exactly like a native tool — **so that** I see concrete evidence of Model Context Protocol integration, and the demo still works cleanly when MCP is switched off.

**This plan's slice:** the agent-side half — make the agent a real MCP *client*. With the `/mcp` route reachable (Plan 05-02), this plan lets the agent discover the companion tool dynamically (`tools/list`), invoke it inside the graph so the call renders identically to a native tool, and degrade to zero MCP tools when `MCP_FETCH_SERVER_URL` is unset. After this plan the agent can discover→invoke→trace an MCP tool end-to-end; Plan 05-04 documents it.

## Acceptance Criteria

- [ ] `backend/agent/mcp_client.py` defines async `discover_mcp_tools() -> (list[BaseTool], list[dict])`, gated by `MCP_FETCH_SERVER_URL`, degrading to `([], [])` on unset OR unreachable (MCP-02, MCP-04).
- [ ] `build_graph` accepts `mcp_tools`/`mcp_schemas`; a collision guard drops MCP tools whose name is already in native `TOOLS`; MCP schemas are merged into the LLM tool list via `agent_node` (MCP-03).
- [ ] `tool_node` executes an MCP tool via `await tool.ainvoke(call['args'])` and produces a `Step` with the same six keys as a native tool call; execution errors become `"Error: ..."` observations (MCP-03).
- [ ] `backend/api.py` lifespan discovers MCP tools once (independent try/except) and threads `app.state.mcp_tools`/`mcp_schemas` through `_run_agent`/`_stream_agent` into `build_graph` (MCP-02, MCP-04).
- [ ] `cd backend && python -m unittest tests.test_mcp tests.test_graph -v` green (DiscoveryGateTests, DiscoveryTests, McpToolNodeTests); full suite has no regressions.
- [ ] SC1 (live invoke) + SC2 (trace parity) + SC3 (unset degrade) confirmed at the Task 4 human-verify checkpoint.

3. **End-to-end wiring (MCP-02/04):** `backend/api.py` lifespan discovers once (independent try/except) and threads the discovered tools/schemas through the request handlers into `build_graph`.

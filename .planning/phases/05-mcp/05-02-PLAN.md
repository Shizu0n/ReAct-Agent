## Phase Goal

**As a** recruiter evaluating the live demo, **I want to** watch the agent discover and call a real tool from a companion MCP server — with the call appearing in the reasoning trace exactly like a native tool — **so that** I see concrete evidence of Model Context Protocol integration, and the demo still works cleanly when MCP is switched off.

**This plan's slice:** make the `fetch_url` server from Plan 05-01 *reachable over HTTP* inside the existing app, and de-risk the single genuine unknown of this phase (Assumption A2: does `stateless_http=True` survive Vercel serverless cold starts?) with a cheap deploy smoke test — before any agent-side integration is built.

## Acceptance Criteria

- [ ] `mcp_server` is mounted at `/mcp` in `backend/api.py`, registered before the `serve_frontend` catch-all (MCP-01 reachability).
- [ ] The app lifespan runs `mcp_server.session_manager.run()` via `AsyncExitStack`, independent of the DB-pool try/except (Pitfall 4).
- [ ] `vercel.json` rewrites `/mcp/:path*` → `/api/index.py` (Pitfall 3).
- [ ] Full backend suite still green; the app imports and builds its route table with the mount present and preceding the SPA catch-all.
- [ ] A2 deploy smoke passes: the deployed `/mcp` route answers a `tools/list` request (not SPA HTML, not 404) on two spaced requests.
